**设计纪律（与 ARCHITECTURE.md §2、§3 一致）**：

1. **HAL 是唯一硬件入口。** RTL8139 骨架的全部寄存器访问经 `src/hal/x86/port.h` 的
   `outb/inb/outw/inw/outl/inl/io_wait`——一个驱动越层直接写端口就是破坏分层宪法，
   并会被 SECURITY.md 的能力门控路径拒之门外。
2. **机制在 netdev/、策略在 config.h。** 环长度、缓冲池容量、MSS 等可调常量在模块头里，
   移入 `src/` 时应收敛到 `config.h`。
3. **自由站立。** 只允许 `#include` `src/include/*`、`src/lib/*`、`hal/x86/port.h` 与 netdev
   内部头；禁止任何标准库函数（用 `kmemset/kmemcpy`），禁止浮点。
4. **默认安全。** 网络栈默认不启用；`netbuf` 的越界请求一律拒绝返回 `-1`/`NULL`，
   网络输入路径**永远不得 panic 内核**（SECURITY.md §4.2 崩溃安全纪律的延伸）。

## 2. NIC 驱动层：RTL8139C+（寄存器级）

为什么选 RTL8139 作为第一块驱动：PCI 即插即用（无需 ISA 跳线）、寄存器窗口小（0x80 字节
PIO 即可驱动）、QEMU 有 `model=rtl8139` 模型可供未来回归测试、文档与参考实现（Linux
`drivers/net/ethernet/realtek/8139too.c`，Donald Becker 原始驱动）在公开世界最充分。
`netdev/rtl8139.{c,h}` 的寄存器映射与初始化序**逐项对照 8139too.c 落实**。

PCI 身份：`vendor=0x10EC device=0x8139`（含 0x8138 与若干克隆 ID）。I/O 基址来自 PCI 配置空间
BAR0（ZenithOS 尚无 PCI 层，故驱动只接受 `io != 0` 由调用方提供，`rtl8139_probe(0)` 一律拒绝——
绝不能把祖父端口（PIT 0x40、PIC 0x20）误认为网卡）。

### 2.1 寄存器映射（I/O 基址偏移）

| 偏移 | 寄存器 | 宽度 | 说明 |
| --- | --- | --- | --- |
| `0x00`–`0x05` | `IDR0..5` (`MAC0`) | 6×8 | MAC 地址，R/W（`Cfg9346` 解锁后可写） |
| `0x08`–`0x0F` | `MAR0..7` | 8×8 | 64 表项多播哈希过滤器 |
| `0x10`–`0x1F` | `TSD0..3` | 4×32 | Tx 状态/描述符：驱动写入 SIZE+ERTXTH 启动 DMA |
| `0x20`–`0x2F` | `TSAD0..3` | 4×32 | 各 Tx 描述符的 DMA 缓冲基址 |
| `0x30` | `RBSTART` (`RxBuf`) | 32 | Rx 环形缓冲区基址（总线地址） |
| `0x37` | `ChipCmd` (CR) | 8 | 命令寄存器（见下） |
| `0x38` | `CAPR` (`RxBufPtr`) | 16 | 主机 Rx 读指针（只写），驱动消费后推进 |
| `0x3A` | `CBR` (`RxBufAddr`) | 16 | 芯片 Rx 写指针（只读） |
| `0x3C` | `IMR` | 16 | 中断屏蔽 |
| `0x3E` | `ISR` | 16 | 中断状态，RW1C（写 1 清除） |
| `0x40` | `TCR` | 32 | Tx 配置（IFG/DMA 突发/重试/环回） |
| `0x44` | `RCR` | 32 | Rx 配置（环长度/接收过滤/FIFO 阈值） |
| `0x48` | `Timer` | 32 | 通用计数器 |
| `0x4C` | `RxMissed` | 24 | 丢包计数，写 1 清除 |
| `0x50` | `Cfg9346` | 8 | 93C46 EEPROM 三线位操作 + Config 寄存器锁 |
| `0x51`/`0x52` | `Config0/1` | 8 | 芯片配置（电源、LED、介质） |
| `0x58` | `MediaStatus` | 8 | 介质状态旁路（内部 PHY 时用 CSCR 更可靠） |
| `0x59`/`0x5A` | `Config3/4` | 8 | WOL/对讲参数（Config4 于 8139A 缺失） |
| `0x5B` | `HltClk` | 8 | `'R'` 跑钟 / `'H'` 停钟（旧芯片低功耗） |
| `0x5C` | `MultiIntr` | 16 | 多功能中断含 early-Rx 使能位（需屏蔽） |
| `0x62`–`0x6A` | `BMCR/BMSR/NWay*` | 16 | 内部 PHY 的 MII 寄存器镜像 |
| `0x74` | `CSCR` | 32 | 芯片状态：链路 OK 位 `0x0400` |
| `0xD8` | `Config5` | 8 | LANWake 等（8139A 缺失） |

`ChipCmd` 位：`RST=0x10`（软复位，完成自清）、`RxEnb=0x08`、`TxEnb=0x04`、`RxBufEmpty=0x01`
（置位表示环空）。

`ISR/IMR` 位（8139too 命名）：`RxOK=0x01`、`RER=0x02`、`TxOK=0x04`、`TER=0x08`、
`RxOverflow=0x10`（环溢出）、`RxUnderrun=0x20`、`RxFIFOOver=0x40`、`PCSTimeout=0x4000`、
`PCIErr=0x8000`。`RxAckBits = RxFIFOOver|RxOverflow|RxOK` 是每帧处理后必须回写的清除位。

### 2.2 Tx：4 描述符弹跳环

`TSD`（TxStatusDesc，32 位）字段：

| 位 | 字段 | 说明 |
| --- | --- | --- |
| 0–12 | `SIZE` | 帧长度，**上限 1792 字节**（`RT_MAX_TX_FRAME`，芯片硬上限） |
| 13 | 主机所有权 | Linux `TxHostOwns=0x2000` |
| 14 | `TUN` | Tx FIFO 欠载（阈值失败，需抬 ERTXTH） |
| 15 | `TOK` | 发送成功（芯片写回） |
| 16–21 | `ERTXTH` | 早发送阈值（单位见数据手册；8139too 取 `TX_FIFO_THRESH 256`） |
| 24–27 | `NCC` | 冲突计数 |
| 29 | `OWIN` | 窗外冲突 |
| 30 | `ABT` | 发送中止 |
| 31 | `CRS` | 载波丢失（100 Mbps 下常置位，不视为错误） |

数据路径（`rtl8139_tx`）：帧拷入下一弹跳缓冲（芯片要求 DMA 安全的连续源，且**无自动填充**，
不足 60 字节需软件补零）→ 写 `TSD = tx_flag | max(len, 60)` 即启动 DMA。`cur_tx`/`dirty_tx`
自由计数，环满判据是两者之差 ≥ 4；`TOK/TUN/ABT` 置位后描述符可回收（`rtl8139_tx_reclaim`）。

### 2.3 Rx：NoWrap 环

`RCR` 位中与环几何相关的：`RBLN` 位 11–12（8K/16K/32K/64K，取 32K）、`RxNoWrap=0x0080`
（禁止帧在环尾折返）。接受过滤位 `AcceptBroadcast=0x08`、`AcceptMyPhys=0x02`（骨架默认：
只收广播 + 本机 MAC）。

每帧前由 DMA 写入 4 字节头：`status u16 | size u16`（size **含 4 字节 FCS**）。消费后：

```text
cur_rx = (cur_rx + size + 4 + 3) & ~3;     /* 4 字节对齐前进 */
CAPR   = (uint16_t)(cur_rx - 16);          /* 见下注 */
```

> `-16` 的语义：CAPR 是芯片用于与 CBR 比较溢出的主机边界，参考实现一律写 `cur_rx - 16`；
> 数据手册对该常量的理由未充分公开。骨架原样照做，**真实硬件 bring-up 时这是首批要复核的
> 魔法常量之一**。

`RxNoWrap` 的代价与收益：芯片不在环尾拆帧，而可能越过环名义长度最多 2048 字节，故调用方
必须预留 `RT_RX_RING_TOTAL = 32768 + 16 + 2048 = 34832` 字节；换来的是每帧单次
`netbuf_append` 即可（64K 环不可设 NoWrap，必须实现双段折返拷贝）。

合法性校验（`rtl8139_rx`）对**不可信硬件状态**一律按最坏情形处理：`size < 8` 或
`size > 1796` 或 `RxStatusOK` 未置位 → 判定「在环中迷失」，按 8139too 现代路径重摆接收器
（RxEnb off→on、恢复 RCR、`cur_rx = 0`），**计错丢弃，永不 panic**。

### 2.4 初始化序（`rtl8139_init`，镜像 8139too `rtl8139_hw_start`）

1. `HltClk = 'R'`（旧芯片出低功耗）；
2. `ChipCmd = RST`，轮询 `RST` 自清（上限 1000 次 × `io_wait()`，超时返回 `-1`）；
3. 读 `IDR0..5` 快照 MAC 到 `d->mac`；
4. `Cfg9346 = 0xC0`（解锁 Config0-4 与 BMCR 写入）→ 回写 MAC → 刷新；
5. `RBSTART = rx_ring` 总线地址（ZenithOS 前 16 MiB 恒等映射，总线地址 = 指针地址）；
6. `ChipCmd = RxEnb|TxEnb`——**必须先于阈值类配置**；
7. `RCR = 32K | NoWrap | FIFO<<13 | DMA<<8 | Bcast | MyPhys`（存 `d->rx_config` 供热复位恢复）；
8. `TCR = IFG96 | DMA<<8 | Retry<<4`（仅 IFG96 不违反 802.3）；
9. `Cfg9346 = 0x00`（锁定）；写 `TSAD0..3`；`RxMissed = 0`；
10. `MultiIntr &= 0xF000`（屏蔽 early-Rx 中断）；复检 `ChipCmd`；`IMR = RT_ISR_ALL`。

**贯穿全文件的posted-write 纪律**：对可能被 PCI 写缓冲延后的寄存器（`Cfg9346`、`MAC`、
`RBSTART`、`TSAD`、`ISR` 回写）写后立即回读同寄存器——这是参考驱动用来对付 8139 已公开的
posted-write 缺陷的标准手法（`rt_w8f/rt_w32f` 帮助函数）。

### 2.5 93C46 EEPROM

`Cfg9346` 复用为 3 线 EEPROM 接口：`DATA_READ=0x01`、`DATA_WRITE=0x02`、`SHIFT_CLK=0x04`、
`CS=0x08`、`ENB=0x80|CS`。读时序：拉 `CS` → 串行移出 读命令 `6 << addr_len | location`
（4+addr_len+1 个时钟）→ 16 个时钟读回大端字。`addr_len` 判定法（同参考实现）：若 word 0
读回 `0x8129` 则为 8 位寻址的 8139 老芯片，否则 6 位。时钟周期用回读 `Cfg9346` 实现
（`rt_eeprom_delay`）。MAC 亦可直接从 `IDR0..5` 寄存器读（上电时由 EEPROM 装载），骨架默认
走寄存器路径，EEPROM 读取保留供探测/烧写场景。

### 2.6 明确的骨架边界

- **无 MMIO**：骨架只用 PIO（`outb/inb` 经 HAL）。8139 亦有 MMIO BAR，待 ZenithOS 有 MMIO
  框架后可切换；PIO 路线在 HAL 宪法下天然正确。
- **无 PCI 配置层**：基址、总线主控使能（`PCI_COMMAND` 的 BusMaster 位，不开则 DMA 不工作）
  由未来的 PCI 层提供。这是 M2 里程碑（§8.3）。
- **无中断处理**：`rtl8139_int_status/ack` 提供给 IRQ 层调用；骨架自身不装中断门。
- **DMA 内存来源**：`rx_ring`/`tx_bufs` 由调用方提供且必须物理连续、DMA 可达（§10 集成清单）。

## 3. NIC 驱动层：NE2000 / DP8390（寄存器级对照）

NE2000 作为**第二驱动目标**保留：ISA/PCI 两个版本（`ne2k_isa`/`ne2k_pci`）QEMU 都有模型，
且寄存器模型是「片上 16 KB 双口 RAM + 页式寄存器文件」，与 RTL8139 的 PIO 窗口形成好对照，
适合作为学生驱动与回归测试基底。寄存器文件在基址 `+0x00..0x0F`，数据口在基址 `+0x10`
（NE2000 为 16 位），复位位在基址 `+0x1F`。

### 3.1 命令寄存器 CR（所有页共用，基址 `+0x00`）

| 位 | 字段 | 值 |
| --- | --- | --- |
| 0 | `STP` 软停机/复位完成 | `0x01` |
| 1 | `STA` 启动 | `0x02` |
| 2 | `TXP` 发送一帧（单次） | `0x04` |
| 3–5 | `RD0..RD2` 远程 DMA 读控制（`RD2=0x20` 中止远程 DMA） | `0x08/0x10/0x20` |
| 6–7 | `PS0/PS1` 页选择（页 0/1/2/3） | `0x40/0x80` |

页选择位与 DMA 控制位共用同一字节是 NE2000 编程的核心陷阱：读页 1 前若带了远程 DMA 位，
CR 写入会同时改变 DMA 状态。骨架惯例：`CR = STA | PSx`（如 `0x22`/`0x62`/`0xA2`）。

### 3.2 页 0（初始化用）

| 偏移 | 写 | 读 |
| --- | --- | --- |
| `0x01` | `PSTART` 环起始页 | `CLDA0` |
| `0x02` | `PSTOP` 环结束页 | `CLDA1` |
| `0x03` | `BNRY` 环边界页（主机消费到哪） | 同（R/W） |
| `0x04` | `TPSR` 发送页 | `TSR` 发送状态 |
| `0x05/06` | `TBCR0/1` 发送字节计数 | `NCR` 冲突计数 / `FIFO` |
| `0x07` | `ISR` 中断状态（RW1C） | 同 |
| `0x08/09` | `RSAR0/1` 远程 DMA 起始地址 | `CRDA0/1` |
| `0x0A/0B` | `RBCR0/1` 远程 DMA 字节计数 | 保留 |
| `0x0C` | `RCR` 接收配置 | `RSR` 接收状态 |
| `0x0D` | `TCR` 发送配置 | `CNTR0` 帧对齐错计数 |
| `0x0E` | `DCR` 数据配置 | `CNTR1` CRC 错计数 |
| `0x0F` | `IMR` 中断屏蔽 | `CNTR2` 丢帧计数 |

`ISR` 位：`PRX=0x01`、`PTX=0x02`、`RXE=0x04`、`TXE=0x08`、`OVW=0x10`（环溢出——必须立刻
重摆 BNRY/CURR，否则芯片拒收）、`CNT=0x20`、`RDC=0x40`、`RST=0x80`。

### 3.3 页 1（MAC 与环指针）

`PAR0..5`（偏移 `0x01..0x06`）= 本机 MAC（可写，需 STOP 模式）；`CURR`（`0x07`）= 芯片将写入
的下一页；`MAR0..7`（`0x08..0x0F`）= 多播哈希（全 0 只收单播+广播；全 0xFF 收全部多播）。

### 3.4 页 3（RTL8019AS 扩展）

`9346CR`（`0x01`，EEPROM 接口）、`CONFIG0..4`（`0x03..0x07`，介质/中断/IO 基址跳线）、
`8019ID0/1`（`0x0A/0x0B`）读回固定签名 `0x50/0x70`——**探测 NE2000 兼容芯片的惯用手段**。

### 3.5 环与远程 DMA

- 环以 **256 字节页**为单位（`PSTART/PSTOP/BNRY/CURR` 都是页号，8 位 → 环 ≤ 64 页 = 16 KB）。
  经典布局：`PSTART = 0x46`、`PSTOP = 0x80`（16 KB 卡取 0x40..0x80）。
- 每帧行前有 4 字节 DMA 头：`RSR` 状态、下一页指针、长度低/高字节（**含该 4 字节头**，奇数
  长度按 2 对齐补齐）。恢复逻辑：`BNRY = next_page - 1`，越 `PSTOP` 回绕。
- 主机取帧用**远程 DMA**：`RSAR`（页<<8）/`RBCR` 写计数 → `CR = STA|RD0(0x0A)` → 从数据口
  `+0x10` 读（NE2000 16 位字读，`DCR.WTS=1`）。
- 发送：帧经远程 DMA 写入 `TPSR` 起始的缓冲，置 `TBCR` 后 `CR |= TXP`。
- **ISA DMA 约束（仅 ne2k_isa）**：ISA DMA 控制器只能寻址低 16 MiB，且网卡 buffer 是片上 RAM
  经 PIO 转运，故 ZenithOS 侧不产生额外边界风险；`ne2k_pci` 走总线主控，风险同 §9 DMA 节。

对 RTL8139 骨架的可复用结论：**两类 NIC 的共同抽象**是「环 + 帧头 + 主机指针/芯片指针 +
越界即重摆」——未来 `src/net/nic.h` 的接口应沿这三条切，驱动差异留在寄存器层内。

## 4. MAC 层与 ARP

### 4.1 以太网帧

```text
| dst MAC 6 | src MAC 6 | EtherType 2 | payload (46..1500) | FCS 4 |
```

最小帧 60 字节（RTL8139 无自动填充，驱动侧补零，§2.2）；FCS 由硬件收发，软件永不计算
（故 `checksum` 模块只管 Internet 校验和）。`EtherType`：`0x0806` ARP、`0x0800` IPv4。

### 4.2 裸机 ARP 表

ARP 包 28 字节（硬件/协议类型各 2、长度各 1、操作 2、MAC×2 + IP×2）。裸机设计取舍：

| 项 | 通用 OS | ZenithOS 计划 | 理由 |
| --- | --- | --- | --- |
| 表结构 | 哈希表 + LRU | 定长数组线性扫描（≤ 16 条） | 16 项内线性扫描比哈希快且零 hashDoS 面 |
| 老化 | 定时器扫描 | PIT tick 计数（`PIT_HZ 100` → 10 ms 粒度，TTL 默认 300 s） | 复用唯一时钟源，无新定时器框架 |
| 网关 | 路由表 | 单一默认网关项（`config` 或 DHCP） | 单链路网络不需要路由协议 |
| 冲突 | 抢占 + 验证 | 覆盖 + 发送前单向探测 | 环境内无恶意 ARP 的前提是 §9 的 DMA/物理边界论 |

ARP 风暴与泛洪是内核解析器唯一会被远程打挂的输入面：处理路径必须有「同一 IP 最多 1 个
未决请求」的限流与有界队列（参考 `KBD_BUF_SIZE 64` 的有界环形哲学）。

## 5. IPv4 与 ICMP

IPv4 头 20 字节（IHL 最小 5）：版本/IHL、TOS、总长、标识、标志/分片、TTL、协议、校验和、
源、目的。裸机取舍：

- **分片**：发送一律置 DF；接收侧**第一阶段不做重组**（超长即丢）——重组状态机是教科书级
  的远程攻击面（去零放、重叠偏移），在用户态/能力制落地前不引这个面。
- **校验和**：`checksum_ip()`；校验「头内带校验和 → 折叠为 0」的零开销判据已在宿主自检中
  验证（向量：`45 00 00 28 …` 头零化算得 `0xF77C`，就位后折叠为 `0`）。
- **路由表**：`lo` + 默认网关两项，静态写在 `config.h`。
- **ICMP**：先实现 echo（type 8/0）——**裸机网络第一个可验证的应用就是 ping**，M5 里程碑。
  type 3 目标不可达用于 TCP 路径反馈。其余类型一律忽略（最小攻击面）。

## 6. TCP：三步握手、重传与拥塞窗口在裸机上的取舍

三步握手（状态机最小集）：

```text
CLOSED --SYN-->                      SYN_SENT 收 ACK+SYN --> ESTABLISHED
                                  （同时回 ACK）
                                  SYN 收到 -> 回 SYN+ACK -> SYN_RCVD 收 ACK -> ESTABLISHED
```

关闭：先实现「主动关闭 + 半关闭忽略」的最小路径（FIN → FIN/ACK），TIME_WAIT 以固定时长
兜底（防旧段串流，代价是净 `NetBuf` 短暂占用——见下窗口约束）。

**裸机 TCP 的核心取舍**（每一条都是当前硬件/内核状态的直接后果）：

| 问题 | 通用实现 | ZenithOS 计划 | 约束来源 |
| --- | --- | --- | --- |
| 时钟 | 高精度定时器轮 | PIT 100 Hz 单一粗 tick（10 ms） | 唯一时钟源；`RTO` 精度即 ±10 ms |
| 重传 | RTT 平滑估计（Jacobson） | 固定初始 RTO（200 ms）+ 指数退避（上限 8 s） | 粗 tick 下 RTT 估计噪声大于信号 |
| 拥塞窗口 | cwnd 以包为单位慢启动/AIMD | **一步慢启动**：`cwnd ∈ {1,2,4,8,16}` MSS 跳变 + 丢包即回到 1 | 静态池深度即硬上限（下段） |
| 接收窗口 | 动态、可缩放 | 固定通告窗口 = 可用 `NetBuf` 数 × MSS，无缩放因子 | 16 个 NetBuf 与粗 tick 下，缩放没有收益 |
| MSS | 1460 | **512–1024 起步** | 弹跳缓冲与 ring 深度；Bilibili 类站点会回降 |
| 重传队列 | 动态 sk_buff 队列 | 复用 `netbuf_ref()`：已发未确认的帧由队列持引用，ACK 后 `netbuf_free` | 静态池 + 引用计数天然支持 |
| 序号比较 | 32 位回卷算术 | 无符号回卷比较宏 | 无浮点、无 64 位依赖（支持但避免） |

**拥塞窗口的诚实结论**：在 100 Hz tick + 16 缓冲的配置下，去模拟 Reno 的 AIMD 曲线没有
意义——裸机网络的第一目标是「可靠地完成一次 HTTP 事务」，所以 cwnd 只做保守的 2 的幂跳变，
把复杂度让给重传的超时管理。等 PIT 升级（如 HPET/局部 APIC 定时器）与 NetBuf 池扩容后再
回到真正的 AIMD。

**DMA 与 TCP 的交互**：Tx 弹跳缓冲是 4×1792 字节静态区（§10），意味着**同一时刻最多 4 帧
在途**——TCP 窗口机制的物理上限。这与上一行表中的 cwnd 跳变上限（16 MSS × 512 = 8 KiB
量级）相配，两者共同决定了 ZenithOS 永远不会是高速下载机，(HTTP/1.1 明文小页面是舒适区)。

## 7. DNS 与 HTTP 1.1

### 7.1 DNS（UDP，最小子集）

- 头 12 字节（ID/标志/QDCOUNT/ANCOUNT/…），问题段 QTYPE=A(1)、QCLASS=IN(1)；
- 只解析**首个 A 记录**，按事务 ID 匹配；**不支持压缩指针**（指针是解析栈炸弹经典面，
  第一版直接拒绝带指针的响应）；
- UDP 512 字节硬上限；超时重发一次后回退硬编码解析器（`config.h`）；
- EDNS0 / DNSSEC / DoH 全部不在范围（TLS 之前不可能，见 §8）。

### 7.2 HTTP 1.1（明文先行）

```text
GET / HTTP/1.1\r\n
Host: <host>\r\n
User-Agent: ZenithOS/6.0\r\n
Accept: */*\r\n
Connection: close\r\n
\r\n
```

- **只做 `Content-Length` 响应**；`Transfer-Encoding: chunked` 需要流式解析器（M7 里程碑，
  有界状态机 + netbuf 链）；
- 头部解析给固定上限（`HTTP_MAX_HEADER 4 KiB`，超长即断开——头部泛滥是 DoS 经典面）；
- 无 cookie/重定向自动跟随/压缩（gzip 需要 zlib —— 又一个密码学量级的库，见 §8）。

## 8. 硬核真相：为什么拦路虎是 TLS

目标「裸机浏览 Bilibili」在当前阶段**不可能**，不是态度问题，是四条硬约束的交集。本节按
SECURITY.md 的诚实口径逐条给出，并给出路线图。

### 8.1 拦路虎一：证书验证（信任链无法在 1.44 MiB 软盘里「凭空出现」）

打开 `https://www.bilibili.com` 意味着：

1. 解析 X.509 DER（ASN.1 长度嵌套）→ 需要 ~2–4 KB 解析器；
2. 验证签名（RSA-2048/PSS 或 ECDSA P-256/Ed25519）→ 需要大数算术（RSA）或椭圆曲线；
3. **信任锚**：Mozilla 根证书集 ~200 个根、去重后仍达数百 KB——`KERNEL_SECTORS 120`
   = 60 KiB 的内核窗口装不下，更遑论软盘镜像扩张与无文件系统存储；
4. 路径构建 + 策略约束（basicConstraints/keyUsage）；
5. **过期校验需要可信墙钟**：ZenithOS 的 RTC（`src/drivers/rtc`）读 CMOS——**半可信输入**
   （SECURITY.md §3.1 明列），且无 NTP 时无法防重放与窗口错位。

→ 结论：**「最小 TLS」与「真实站点 TLS」是两个数量级的工程**，前者可自签信任锚演示，
后者需要第一个版本的用户态/文件系统（存根证书）与可信时间源。

### 8.2 拦路虎二：密码学栈体积与 60 KiB 预算

TLS 1.2 客户端的最小集合：AES-128-GCM（或 ChaCha20-Poly1305）+ SHA-256/HKDF + ECDHE
（P-256 或 X25519）+ RSA/Pkcs1 验签 + TLS 记录/握手状态机。经验体积 20–50 KB C 代码，
连同密钥调度表与 SNI/ALPN 逻辑，对当前 21,173 B / 61,440 B（34.5% 占用）的内核窗口是
**实质性挤压**；TLS 1.3 更紧（0-RTT/密钥更新）且 PHP 类站点常强制 1.2+。

> 与 ZenithOS 自身文化的诚实呼应：lib/math（定点数学库）已经为 scene3d 做了「不引入浮点」
> 的同类取舍。TLS 的取舍则是「不在 v6.0 引入」。

### 8.3 拦路虎三：无时钟无熵源

- **熵源**：无 RDRAND（模型依赖）、无硬件 RNG、无中断抖动采集框架。会话密钥的质量取决于
  这一项——在无熵源机器上做 TLS 等于用可预测密钥（SECURITY.md §2.2 的「构建主机内鬼」级别
  风险）。M2 起必须先落地「RDRAND 探测 + RTC/中断混合池」（Fortuna 类最小实现）。
- **时钟**：重传超时、TLS 记录序号防重放、证书有效期全部依赖时间；PIT tick 只给相对时间，
  CMOS 墙钟不可信（可被物理改写），NTP 本身又需要网络与（最优路径的）TLS。
- **CPU 侧通道**：恒定时间算术在 ring 0 单核上不是第一优先矛盾，但写不下「我们考虑过」
  之外的承诺。

### 8.4 拦路虎四：Bilibili 站点现实

HSTS 强制 HTTPS、TLS 1.2/1.3、HTTP/2（ALPN 协商——意味着 TLS 客户端要带 ALPN 扩展并处理
二进制分帧，或降级 HTTP/1.1 服务器是否容许）、现代化证书链（多级、含跨签名）。
**「能 ping 通」到「能解析其证书链」之间隔着 §8.1–§8.3 的全部**。

### 8.5 诚实里程碑路线

| 里程碑 | 内容 | 状态标注 |
| --- | --- | --- |
| M0 | `netdev/` 骨架编译通过 + 宿主级单元自检（netbuf/checksum 27 项全过） | **[已实现]** |
| M1 | RTL8139 寄存器级骨架（reset/init/Tx/Rx 环、寄存器映射逐项对照 8139too） | **[已编译·未接线]** |
| M2 | PCI 配置层（type 1 周期、BAR0 解析、BusMaster 使能 + PMM 分配 DMA 环）+ 熵源（RDRAND 探测 + 混合池） | [目标架构]（净依赖：`src/drivers/` 未接线） |
| M3 | IRQ 路由 + ISR 接 `rtl8139_int_*`；PIT 接线提供 TCP tick | [目标架构] |
| M4 | **RTL8139 TCR 环回自测**（不需要外部交换机：自发自收整条 DMA 路径） | [目标架构]（首个真实验证点） |
| M5 | ARP + ICMP：局域网 ping 通 | [目标架构] |
| M6 | 最小 TCP（三步握手 + 固定 RTO + 退避）+ HTTP 明文 demo 站（本机 `python -m http.server`） | [目标架构] |

| M9 | Mozilla 根子集（需文件系统或镜像扩容）→ 公网 HTTPS → Bilibili | [目标架构]（依赖 v6.1/v6.2 的用户态与存储） |

> 路线图的真实读法：M0–M1 是本任务的全部交付；M2–M4 是**在本机无 QEMU 的条件下唯一可能
> 完成的下一阶段**（PCI/IRQ 层属内核本分，环回自测免外部设备）；M8–M9 与 v6.1 能力制进程、
> v6.2 用户态/文件系统/可信更新**共享路线**——TLS 不是「再加一个模块」，而是把 SECURITY.md
> §5.2/§5.3 的里程碑拉到网络面上。

## 9. 安全视角：网络面带来的新攻击面

本节把 SECURITY.md 的四原则落到网络栈，并更新其威胁模型（该文档 §2.2 现写「网络攻击者：
**不适用**（无网络栈）」——netdev/ 落地后这句话进入过渡态）。

### 9.1 新攻击面清单

| 面 | 来源 | 缓解（现状） | 缓解（目标） |
| --- | --- | --- | --- |
| **无缝 Tx/Rx 边界** | DMA 环上的 `status`/`size` 字段由**不可信硬件**写入 | 有界校验（8 ≤ size ≤ 1796、判失败即重摆接收器），网络路径零 panic | 同 + 环区页对齐隔离 |
| **协议解析器** | ARP/IPv4/TCP/HTTP 头部长度字段全部远程可控 | 每层定长上界 + 拒绝即丢（`netbuf_append/pull/trim` 全部拒绝越界） | 同 + fuzz 门禁（SECURITY.md §5.4） |
| **DMA** | RTL8139 是 32 位总线主控，**可读写全部物理内存** | 只把 PMM 页给 DMA；无 IOMMU | v6.2 IOMMU/受限 DMA 窗（SECURITY.md §3.4 的兑现） |
| **无 ASLR/单地址空间 ring 0** | 任何解析 bug = 全权 | 缩小解析面（见 §4–§7 的「最小子集」选择） | v6.1/v6.2 进程隔离 |
| **熵源缺失** | 密钥可预测 | 未实现 TLS，无密钥材料 | M2 混合熵池 |
| **MAC 隐私** | 网卡固定 MAC 可被网络侧追踪 | 默认不启用网络 | 软件可配 MAC + 随机化策略 |
| **中断风暴** | 远程可触发高频率 IRQ | 待 IRQ 层：速率限制 + 中断关闭轮询兜底 | M3 设计时落实 |

### 9.2 与 SECURITY.md 的呼应（变更预告，待 Lead 认可后回写）

- **§2.2 攻击者表**：「网络攻击者」从「不适用」升为**首要威胁**（物理攻击者并列）；
- **§3.1 输入清单**：新增「DMA 环帧头」「ARP/IPv4/TCP 头部」两行不可信输入；
- **§3.4 物理攻击与 DMA**：「启用总线主控设备前必须制定 IOMMU 或受限 DMA 窗」从**前置条件**
  变为**已部分激活**（netdev/ 提供了第一个总线主控驱动骨架）；
- **§4.4 明确不声称**：新增「不防御远程网络攻击（网络栈未接线）」；
- **§6 待验证不变量**：新增「网络输入路径永不 panic」「DMA 环指针变更必经 HAL」。

### 9.3 netbuf 的防御性设计（可被 SECURITY.md §6 引用为不变量）

- 越界请求一律 `-1`/`NULL`，没有「尽力而为」的截断；
- 引用计数饱和于 `0xFFFF`，永不回卷到 0 制造「在用即释放」；
- 释放后清零游标（`head/len/tag`），防止陈旧状态随复用泄漏；
- 双 `free` 是空操作（free-list 不被破坏，宿主自检已覆盖）；
- 池是**静态定长**，网络负载最坏情形不吃内核堆（与 heap 的 bump 分配器风险隔离）。

### 10.1 验证矩阵（本任务全部交付的验证强度）

宿主自检的实现方式（诚实披露）：测试 `main()` 放在**系统临时目录**（仓库之外），经
`tcc -Wall -nostdinc -I ... -o exe` 编译后运行；测试源码 `#include` 了 `lib/string.c`、
`netbuf.c`、`checksum.c` 三个实现文件。**仓库里没有新增任何测试文件**——netdev/ 只含六个
交付文件，临时文件会话结束后不再维护；入仓的等价物是 `checksum_selftest()`（M4/M6 接线时
在内核 init 路径调用）。

**为什么 rtl8139 无法运行时测试**：1) ZenithOS 无 PCI 配置层，无法枚举/使能设备；
2) IRQ 与 DMA 依赖 IDT/PIC 接线（`[已编译·未接线]`）；3) 本机无 QEMU，且
`tools/emulate.mjs` 背后 v86 **没有 NIC 模型**。§8.5 的 M4（TCR 环回自测）是这一切的第一个
真实验证点，但它本身就以 M2/M3 为前提。

### 10.2 移入 `src/net/` 的集成清单（需 Lead 放行）

1. **目录与命名**：`netdev/*.{c,h}` → `src/net/*.{c,h}`；`build.js` 自动发现
   `src/**/*.{c,asm}`，**无需改构建系统**；函数前缀 `rtl8139_*`/`netbuf_*`/`checksum_*`
   与现有驱动命名一致（`serial_*`/`vga_*`），寄存器常量 `RT_*` 前缀避免与未来 PCI 层冲突。
2. **BSS 预算（关键）**：`NetBuf` 池 = 16 × 1548 = **24,768 B .bss**；当前
   `bss_end = 0x166E8`，距 `VGA_BACKBUF(0x20000)` 约 39 KiB——池可容纳但**挤压严重**，
   建议同时把 `NETBUF_POOL_SIZE` 调到 8–12 或先启用分页把内核数据区上移。
3. **DMA 环不能放 1 MiB 内窗口**：`RT_RX_RING_TOTAL(34832) + RT_TX_BOUNCE_TOTAL(7168)
   ≈ 41 KiB`，远超 `0x10000–0x20000` 的剩余空间。**必须由 PMM 在 1 MiB 以上分配连续页**
   （Rx 环需 9 页连续、Tx 区 2 页连续），并依赖前 16 MiB 恒等映射保证总线地址 = 指针地址。
4. **接线顺序**：PCI 层（BAR0 + BusMaster）→ IRQ 路由 → `rtl8139_init` →
   `checksum_selftest()` 入 init 报告 → ARP/ICMP/TCP 按 M5–M6 推进。
5. **合规**：模块头注释里的 `[已编译·未接线]` 标注需在接线时同步更新；ARCHITECTURE.md §8
   的目录树增加 `src/net/` 分支；SECURITY.md §9.2 的五处回写。
